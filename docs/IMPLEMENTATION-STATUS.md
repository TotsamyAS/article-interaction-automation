# Состояние реализации

## Подготовлено

- Backend FastAPI: общий исполнитель запросов, 120 воспроизводимых записей, 15 экспериментальных задач и отдельная тренировка.
- SQLite: миграции, постоянное хранение, проверка неизменности протокола/эталонов, транзакции и идемпотентные попытки.
- Доступ: индивидуальные многоразовые приглашения, HttpOnly-cookie, роли `participant`/`researcher`, владение ресурсами и отзыв приглашения без удаления прогресса.
- M1 frontend: последовательные фильтры, preview, таблица, группировка/агрегат/экстремум, сортировка, CSV и итоговая проверка.
- M2 frontend: адаптированный `TagInput`, подсказки + ручной структурированный ввод, единая кнопка «Выполнить» и backend-компиляция в общий `Query`.
- Переиспользованы `TagInput`, `LiveSearchProgress`, `ConfirmDialog`, `AppToast`; табличная часть адаптирована из `Corpus` без зависимостей старого проекта.
- Frontend на Bun + Svelte 5, публичный порт `3033`; same-origin proxy к внутреннему backend.
- Task Mining frontend: ввод, pointer/scroll, focus, navigation, request start/finish; серверный курсор сохраняет sequence/offset при reload активной пробы.
- Исследовательский экран: только Excel/CSV-выгрузки, без отдельной панели аналитики.
- M3 frontend/backend: естественный текст → OpenRouter/OpenAI-compatible strict structured output → Pydantic `Query` → общий executor; подробный журнал интерпретации и ошибок. M3 model/prompt/temperature фиксируются по вызовам и не делают dataset volume несовместимым при обновлении приложения.
- M4–M5 явно недоступны; агентный M5 по текущему решению пользователя не реализуется.

## Проверки предыдущего этапа

### Выбор поля и исключения M2 — 23.09.2026

Распознавание названия поля вынесено в общий frontend-парсер: `Статус` и `Статус:` открывают черновик значения. Единственная подходящая подсказка автоматически выделяется для Enter/Tab. Добавлены `НЕ` перед полем/значением и пошаговая подсказка «Исключить»; на готовой группе показана отметка исключения. Все формы используют прежний backend-контракт `!=`, без изменений схемы и backend. Сохранены «ИЛИ» для положительных альтернатив и «И НЕ» для исключений одного поля.

До исправления новый тест `НЕ Приоритет: Низкий` падал; после исправления **9 проверок парсера прошли**. Это проверки синтаксиса и сериализации без DOM. Локальные `svelte-check` — **0 ошибок, 0 предупреждений**, production build через Vite API с `envDir: false` — успешно; Bun 1.3.14. Docker не использовался, `.env` не читался. Проверка поведения в браузере остаётся ручной.

Точное сообщение пользователя «Используйте формат…» отсутствует в текущих `frontend/src` и `backend/app`. Старая сборка — возможная причина, без проверки запущенного приложения она не подтверждена. Для установки патча пользователь пересобирает frontend: `docker compose build frontend`, затем `docker compose up -d --no-build --no-deps frontend` и обновляет страницу. Ручной сценарий: `Статус` → Enter → `В работе` → Enter → `ИЛИ` → Enter → `На ревью` → Enter; затем `Исключить` → Enter → `Приоритет` → Enter → `Низкий` → Enter. Ожидаются одна группа статусов и отдельное исключение низкого приоритета; ввод остаётся в одной строке. Тот же фильтр должен получиться при ручном `НЕ Приоритет: Низкий`.

```sh

docker compose up -d --no-build
docker compose exec backend python -m pytest -q -p no:cacheprovider
docker compose exec backend python tests/smoke_server.py
docker compose exec backend python -m pip check
```

Затем:

```sh
docker compose exec backend sh scripts/invite.sh P001
docker compose exec backend sh scripts/invite.sh RESEARCHER --role researcher
```
