# Актуализация проекта статьи — M4 self-hosted ASR (30.09.2026)

- Принятое ранее решение использовать browser Web Speech API отменено по эксплуатационной причине: из РФ распознавание требовало VPN, а VPN одновременно ухудшал доступ к стенду. Это создавало систематический внешний фактор, не связанный с исследуемым способом взаимодействия.
- Реальный стенд теперь определяет M4 как **голосовой канал поверх M3**: браузер записывает речь (`MediaRecorder`), backend локально распознаёт её `GigaAM-v3/e2e_rnnt` (CPU `float32`, `ru`, short-form до 20 секунд), затем transcript без ручного редактирования идёт в тот же RouterAI compiler/executor. Концептуальная роль M4 в сравнении режимов не меняется; меняется только ASR-реализация.
- Сырой звук не сохраняется. Для воспроизводимости сохраняются ASR protocol metadata и `m4_transcriptions` (transcript, длительность, байты, модель/compute type, `Tasr_ms`). Task Mining остаётся сквозным: речь — активность участника, серверное ASR-ожидание — отдельный request interval.
- В тексте статьи следует заменить упоминания Web Speech API/Firefox-ограничения на self-hosted GigaAM-v3 и явно описать это как изменение между проектом статьи и фактическим экспериментальным стендом.

# Проверка проекта статьи перед разработкой

## Принятые решения и расхождения со стендом — 29.09.2026

Этот раздел фиксирует состояние на 29.09 и заменяет более ранние пометки ниже о том, что M4/M5 «не выбраны» или «не реализуются». Решение по M4 из этого раздела, в свою очередь, заменено актуализацией от 30.09 выше; старые записи оставлены как история решений.

- **M3:** реальный стенд использует RouterAI, а не OpenRouter: OpenAI-compatible endpoint `https://routerai.ru/api/v1`, `google/gemma-4-26b-a4b-it`, `temperature=0`, strict structured `Query`, затем общий детерминированный executor. В статье нужно описывать M3 именно как LLM-компилятор, а не отдельный вычислитель.
- **M4:** ASR выбран окончательно — browser Web Speech API. Это важное отличие от проекта статьи, где ASR можно было прочитать как отдельный серверный модуль. Backend аудио не принимает: `SpeechRecognition`/`webkitSpeechRecognition` (`ru-RU`) даёт transcript, затем работает тот же M3 RouterAI compiler/executor. В Firefox участника заранее просят открыть ту же персональную ссылку в другом современном браузере; M4 там не стартует. Transcript нельзя вручную исправить, можно перезаписать речь.
- **M5:** агентная система больше не открытый вопрос. Реализуется протокол из `benchmarks/m5_agent_benchmark.ipynb`: RouterAI + та же Gemma, семь атомарных tools — `search_tasks`, `filter_by_field`, `group_by`, `aggregate`, `find_extremum`, `sort`, `export_result`; последовательное выполнение tool calls; максимум 12 LLM-шагов. Полная наблюдаемая trajectory сохраняется, скрытые рассуждения не требуются. Финальная семантика проверяется общим engine/эталоном.
- **Task Mining — сквозное требование статьи:** ни M4, ни M5 не обходят журнал участника. Во всех M1–M5 сохраняются действия браузера и границы системных запросов. Для M4 добавлены `speech_started/speech_finished`, чтобы произнесение вошло в активное время; ожидание системы вычитается. M5 trajectory — отдельный системный слой «что делал агент», а Task Mining — слой «что делал участник»; эти данные нельзя смешивать как одну метрику.
- **Инженерная проверка M5:** 15 фиксированных benchmark-задач × 5 повторов = 75 запусков; 73 успешных, 2 ошибки → **97,33%**. Это evidence работоспособности/стабильности agent pipeline перед экспериментом, не результат пользовательского исследования и не оценка сравнительной эффективности M5.
- **Что исправить в тексте статьи:** согласовать список M5 tools во всех разделах (обязательно `find_extremum`); убрать представление M4 ASR как серверного сервиса; не обещать сравнение распознавания с «эталонной фразой», пока отдельный gold transcript реально не собирается; для M3–M5 зафиксировать RouterAI/Gemma и разделить browser Task Mining от M5 agent trajectory.

## Последние два замечания закрыты

### Метрики незавершённой пробы — закрыто (§5.6)

Теперь явно разделены фактические измерения и штрафные значения для анализа:

- журнал сохраняет фактическую длительность, число попыток и причину завершения;
- штрафные значения: Tcorrect = 300 секунд, A1 = 0, Nretry = Nmax − 1 = 4;
- фактические и штрафные значения хранятся раздельно.

Проверены последствия на двух примерах:

| Сценарий | Фактические данные | Значения для анализа |
|---|---|---|
| Пять неуспешных попыток за 40 секунд | 40 секунд, 5 попыток, 4 повтора; исчерпаны попытки | Tcorrect = 300, A1 = 0, Nretry = 4 |
| Одна неуспешная попытка, затем истечение пяти минут | 300 секунд, 1 попытка, 0 повторов; истёк лимит времени | Tcorrect = 300, A1 = 0, Nretry = 4 |

Различие между реальными повторами и штрафным числом теперь намеренное и явно описанное; приложение может сохранить оба значения без потери измерений. В исходных данных неуспешной пробы корректный результат отсутствует, а 300 секунд относятся к отдельному показателю для анализа.

### Порядок проб — закрыто (§5.5 и §5.7)

Оба раздела теперь задают одинаковую последовательность:

1. Пять последовательных блоков режимов в порядке таблицы 4.
2. Внутри каждого блока — C1 → C2 → C3 с назначенным этому блоку вариантом.
3. Четыре перерыва по две минуты между блоками.

Итого 15 основных проб и 8 минут фиксированных перерывов. Вложенность режимов и уровней однозначна.

## Что не требует нового согласования перед началом разработки

- Конкретная D0, воспроизводимая генерация 120 записей и хранение версии набора — инженерные решения в рамках уже описанных правил.
- Для перечисленных задач достаточно объединения фильтров через AND и оператора in для альтернативных статусов. Неоднозначные произвольные сочетания AND/OR из плоского массива нельзя молча интерпретировать; поддерживаемую семантику нужно явно описать в контракте. Универсальный конструктор логических выражений для текущего набора задач не требуется.
- Правило AVG можно реализовать как абсолютную погрешность не более 0,01; округление для отображения не должно подменять эту проверку.
- В описании C3a по-прежнему не учтён COUNT в перечне операций, хотя в C3c/C3e он учтён. Это замечание к обоснованию одинакового TCI, а не препятствие выполнению задач. Для приложения уровни и заявленные значения TCI могут быть метаданными каталога; автоматический пересчёт индекса не заявлен как функция стенда.
- Перечни агентных инструментов в §4.3, §4.4 и §5.3 всё ещё различаются. Их окончательное согласование относится к отложенному подключению агента и не мешает реализовать общее ядро.
- Редактура статистических выводов, библиографии и вёрстки не включена в эту проверку.
