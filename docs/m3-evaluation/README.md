# Материалы для выбора модели M3

Снимок 28.09.2026. Сформирован локально из `build_system_prompt`, `query_response_schema`, `generate_dataset` и действующего `backend/config.json`. Без чтения `.env`, обращения к провайдеру или базе участников. Рабочие модель и prompt не изменены.

- `system-prompt.txt` — точный системный prompt `m3-query-v2`, D0 = 2026-09-01, с четырьмя существующими few-shot примерами.
- `query.schema.json` — точная схема, передаваемая API отдельно как strict `response_format.json_schema`.
- `arena-input.txt` — инструкции + схема + один запрос для вставки в обычный чат. Ожидаемый ответ сюда не включён. Это приближение: один пользовательский message не воспроизводит роли system/user и принудительное соблюдение схемы API.
- `example.json` — запрос, ожидаемый Query и результат общего детерминированного engine. Эталон не является ответом какой-либо LLM. Получены 4 записи рабочего цикла 5; внутреннее значение набора — `Спринт 5`.

Снимок не является новым источником runtime-промпта. После изменения `llm.py`, схемы, D0 или набора его следует сформировать заново.

Обнаруженное ограничение текущего prompt: отсутствуют явные соответствия «направление работ» → `epic`, «рабочий цикл» → `sprint`, «Рабочий цикл N» → сохранённое значение «Спринт N». Примеры тоже используют старые названия. До финального сравнения моделей нужно согласовать и зафиксировать эту правку; в данном снимке исходник намеренно показан без изменений.

## Как сравнивать

Каждый запрос проверять в новом чате с одинаковыми инструкциями. Для окончательного решения — тот же API, роли сообщений, схема и настройки декодирования, которые будут использоваться в приложении. Отдельно учитывать валидность JSON, соблюдение схемы, смысл фильтров/операций, эквивалентность результата на наборе и задержку. JSON не обязан совпадать побайтно: например, порядок независимых AND-фильтров несущественен.

Предлагаемый начальный тест: все 15 задач × 5 независимых перефразировок = 75 запросов на модель. Покрыть отрицания, null, периоды от D0, альтернативы статусов, группировку, агрегаты, равные максимумы и CSV. Не включать оцениваемые запросы с ответами в few-shot. Это пилотный набор, а не доказательство надёжности на любых формулировках.

Доказанного минимального размера пока нет. Инженерная отправная точка — dense instruct-модель класса 4B, например [Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507) (официальная карточка: 4 млрд параметров, non-thinking). Сравнить с классом 8B, например [Qwen3-8B](https://huggingface.co/Qwen/Qwen3-8B), фиксируя режим reasoning. Если требуется найти именно нижний предел, добавить класс 1–3B и заранее определить приемлемые ошибки/задержку. Размер сам по себе не гарантирует успех; рекомендации не являются измерением на нашем стенде. Доступность названных моделей в LMArena не проверена.
