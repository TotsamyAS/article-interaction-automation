# Экспериментальный стенд

Стенд по разделам 4–5 [проекта статьи](docs/article_project.docx): FastAPI backend + Svelte 5 frontend на Bun. Реализованы M1–M5, 120 воспроизводимых записей, 15 экспериментальных задач, тренировка, попытки, сквозной Task Mining, доступ по многоразовым приглашениям и выгрузка CSV/Excel. M3 и M4 используют RouterAI как LLM-компилятор в общий `Query`; M4 записывает речь через `MediaRecorder` и распознаёт её через RouterAI Audio Transcriptions, причём ASR-модель задаётся в `backend/config.json`. M5 использует RouterAI как агентный planner над семью атомарными инструментами.

Frontend работает на `http://localhost:3033`. Он является единой браузерной точкой входа и проксирует `/api`, `/health`, `/docs` и `/openapi.json` во внутренний backend. Это сохраняет один origin для HttpOnly-cookie и проверки cross-origin запросов.

## Запуск в WSL/Linux

Пользователь вручную создаёт корневой `.env` и задаёт секреты:

```text
INVITATION_SIGNING_KEY=<случайное значение длиной не менее 32 байт>
ROUTERAI_API_KEY=<ключ RouterAI>
```

Значение генерируется и хранится пользователем локально; его не следует передавать в чат, коммиты или логи. Несекретные настройки принадлежат `backend/config.json` и `frontend/config.json`.

Сборка и запуск:

```sh
docker compose up -d --build
```

M4 ASR не требует локальных весов: backend вызывает RouterAI `POST /api/v1/audio/transcriptions`. По умолчанию `asr_model` — `nvidia/nemotron-3.5-asr-streaming-multilingual-0.6b`; модель можно заменить на любой совместимый RouterAI transcription model без изменения кода.

Открыть стенд: `http://localhost:3033`. API-документация: `http://localhost:3033/docs`.

Dockerfile frontend выполняет `bun run check` и `bun run build` во время сборки. Backend после сборки проверяется отдельно:

```sh
docker compose exec backend python -m pytest -q -p no:cacheprovider
docker compose exec backend python tests/smoke_server.py
docker compose exec backend python -m pip check
```

Данные сохраняются в именованном томе. Backend наружу не публикуется; доступ к нему идёт через frontend-прокси. Для внешнего развёртывания нужен HTTPS-origin в `backend/config.json` (`public_base_url`) и соответствующая внешняя маршрутизация на frontend.

## Приглашения и вход

Если `sh scripts/invite.sh` сообщает `set: Illegal option -`, причина — Windows-переносы CRLF в старом образе. Скрипты теперь сохраняются с LF (`.gitattributes`, `.editorconfig`), а Dockerfile дополнительно убирает CRLF и проверяет запуск `--help` без доступа к секретам. Для применения исправления пересоберите и пересоздайте только backend; том с прогрессом сохраняется:

```sh
docker compose build backend
docker compose up -d --no-build backend
docker compose exec backend sh scripts/invite.sh --help
```

Ссылки выпускаются только внутри запущенного backend-контейнера:

```sh
# Participant
docker compose exec backend sh scripts/invite.sh P001

# Researcher with access to aggregate analytics
docker compose exec backend sh scripts/invite.sh RESEARCHER --role researcher

# Revoke the invitation; preserve experiment data
docker compose exec backend sh scripts/invite.sh P001 --revoke
```

Команда печатает credential-ссылку. Не сохраняйте её в общих логах. Ссылка многоразовая: повторный переход снова выдаёт HttpOnly-cookie и открывает `/`, где frontend восстанавливает сессии и прогресс через `/api/me`. Публичной регистрации, ФИО, email и паролей нет.

Участник видит только свои сессии/пробы. Исследователь получает экран выгрузки Excel/CSV без отдельной аналитической панели.

## Пользовательский сценарий M1–M5

На каждое задание — **25 попыток и 25 минут**. Кнопка **«Как работать»** открывает боковую памятку: примеры M1/M2, клавиши ввода и словарь. Запрос при закрытии памятки сохраняется; время запущенной пробы продолжает идти. «Эпик» в интерфейсе теперь называется **«Направление работ»**, «Спринт» — **«Рабочий цикл»**, «Дедлайн» сохраняет название. В M1 значения фильтра выбираются **галочками**, Ctrl не нужен.

Разные ссылки приглашения можно открывать в разных вкладках: участник закреплён за вкладкой, скачивания используют его же доступ. Одну пробу нельзя одновременно редактировать в двух вкладках браузера: вторая покажет пояснение. Закройте первую и обновите вторую для продолжения. После установки этого патча заново откройте каждое приглашение в нужной вкладке.

Обновление выполняет пользователь:

```sh
docker compose build backend frontend
docker compose up -d --no-build
```

Миграция сохраняет прогресс и прежние метрики завершённых проб; активные и ожидающие получают новые лимиты без сброса попыток и прошедшего времени. В Excel/CSV указаны лимиты каждой пробы и версия терминологии. Обновление не требует удаления тома.

1. Открыть персональную ссылку участника. После редиректа загрузится frontend на `3033`.
2. Создать основную или тренировочную сессию. Повторный вход показывает уже существующий прогресс.
3. Нажать «Начать пробу». Только после серверного `/start` показывается формулировка и запускается таймер.
4. В M1 вручную добавлять фильтры, применять preview, задавать группировку/агрегат/экстремум/сортировку/CSV и нажимать «Проверить результат».
5. В M2 собрать структурированный запрос через TagInput и один раз нажать «Выполнить».
6. В M3 описать требуемый результат обычным текстом. Backend отправляет текст и фиксированный prompt в RouterAI, принимает строго структурированный `Query`, валидирует его и выполняет тем же детерминированным engine, что M1/M2.
7. В M4 произнести запрос. Браузер пишет аудиофрагмент до 20 секунд через `MediaRecorder` и отправляет его по HTTPS на backend; backend передаёт запись выбранной в `config.json` ASR-модели RouterAI, после чего текст проходит ровно тот же RouterAI-компилятор и общий executor, что M3. Расшифровка перед отправкой не редактируется: при ошибке участник записывает запрос заново. Аудио после распознавания не сохраняется. VPN и Web Speech API не нужны; M4 поддерживается в актуальных Chrome/Edge/Firefox при наличии `MediaRecorder` и разрешения микрофона.
8. В M5 ввести цель обычным текстом. RouterAI-агент выбирает последовательность из семи атомарных инструментов (`search_tasks`, `filter_by_field`, `group_by`, `aggregate`, `find_extremum`, `sort`, `export_result`), максимум 12 LLM-шагов. Итоговый `Query` и результат всё равно проходят общий executor и проверку эталона.
9. При задаче с CSV успешная попытка запускает скачивание результата. Попытки остаются идемпотентными на сетевом повторе.

Task Mining обязателен во всех M1–M5: frontend журналирует ввод, pointer/scroll, focus, navigation и парные `request_started/request_finished`. M4 дополнительно пишет `speech_started/speech_finished`, поэтому произнесение учитывается как активная работа, а ожидание системы вычитается отдельно. Внутренняя M5 trajectory (LLM/tool calls) хранится отдельным системным журналом и не подменяет пользовательский Task Mining. При перезагрузке активной пробы sequence/offset продолжаются с серверного курсора, а не начинаются заново. В аналитической таблице `events` каждая строка содержит `participant_code`, `trial_position`, `occurred_ms`, `duration_ms` и `duration_complete`: точечные события имеют нулевую длительность, парные интервалы — измеренную, а незакрытые интервалы right-censored на границе наблюдения.

Между пробами и блоками обязательного ожидания больше нет. После завершения пробы сразу нажмите «Начать пробу» для следующей. Её собственный лимит времени сохранён. При обновлении существующей базы миграция сохраняет прогресс и добавляет историю отмены перерывов в метаданные Excel/CSV ZIP.

Ошибки журнала действий показываются отдельным предупреждением: конфликт вкладок, нарушение порядка времени либо выход за время пробы. Уже сохранённый ответ при этом остаётся сохранённым. Таймер и журнал используют серверную длительность и монотонные часы браузера; настройка часов компьютера участника на них не влияет.

## M2 TagInput

Исключение: `Исключить` → Enter → `Приоритет` → Enter → `Низкий` → Enter. Или ввести целиком `НЕ Приоритет: Низкий` (также допустимо `Приоритет: НЕ Низкий`). На группе появляется отметка «Исключить». Ещё одно исключаемое значение того же поля добавляется через `И НЕ`; другое условие — через `И`.

Переиспользован и адаптирован `frontend/references/TagInput.svelte`. Все шаги выполняются в **одном постоянном поле ввода**. Введите `Статус` → Enter → `В работе` → Enter → `ИЛИ` → Enter → `На ревью` → Enter: останется одно условие с двумя альтернативами. Enter и Tab подтверждают непустой ввод, сохраняя фокус в той же строке. После готового тега ввод `И` начинает другое условие; `ИЛИ` продолжает прежнее. Готовые поле и значения редактируются кликом; Esc отменяет текущую правку.

Группировка вводится здесь же: `Группировка` → Enter → `направление работ` → Enter, затем `Итог` → Enter → `количество` → Enter. Для поиска максимальной группы добавьте `Экстремум` → `максимум`; для экспорта — `Экспорт` → `CSV`. Действия доступны среди общих подсказок, отдельного переключения формы нет.

Синий шаг — поле, зелёный — значение, фиолетовый — связка или продолжение запроса; каждый шаг подписан словами. Можно также ввести целиком `Статус: В работе ИЛИ На ревью`. Незавершённое условие нужно дополнить или отменить перед выполнением. На пустой строке Tab перемещает фокус обычным образом. Произвольные OR между разными полями и скобки не поддерживаются и не удаляются молча.

Пример C2: `Направление работ: Платежи`, `Статус: В работе / На ревью`, `Период: 14 дней`, `Итог: количество`. Поддерживаются фильтры по полям набора, сравнения дат/оценки, альтернативы через `/`, операции `Период`, `Итог`, `Группировка`, `Экстремум`, `Сортировка` и `Экспорт: CSV`. Свободный текст не интерпретируется; решение задачи автоматически не подставляется.

## M3 и M4 через RouterAI

M3 использует `backend/app/llm.py`: OpenAI-compatible `POST /chat/completions` RouterAI → strict JSON Schema → Pydantic `Query` → общий executor. По умолчанию выбран `deepseek/deepseek-v4.1-flash`, `temperature=0`, `seed=0`, endpoint `https://routerai.ru/api/v1`; timeout и модель находятся в `backend/config.json`, API key — только в корневом `.env` как `ROUTERAI_API_KEY`.

Системный prompt генерируется из фактических допустимых значений набора данных и фиксированной D0, задаёт точную семантику дат, NULL, меток, агрегатов, группировки, экстремума и CSV. Few-shot примеры синтетические и не содержат экспериментальные формулировки C1a–C3e. Структурированная схема строится непосредственно из Pydantic-контракта `Query`. Runtime prompt M3/M4 имеет версию `m3-query-v3` и явно связывает термины интерфейса «Направление работ»/«Рабочий цикл» с каноническими полями набора.

M4 использует RouterAI ASR: `MediaRecorder` передаёт аудио на `/api/trials/{trial_id}/m4-transcribe`, backend вызывает OpenAI-compatible `POST /audio/transcriptions`, а дальше используется тот же M3-компилятор RouterAI и тот же детерминированный executor. `asr_model` в `backend/config.json` задаёт конкретную RouterAI-модель; значение по умолчанию — `nvidia/nemotron-3.5-asr-streaming-multilingual-0.6b`. Аудио после распознавания не сохраняется; в аналитике сохраняются transcript и технические метаданные ASR. Task Mining фиксирует границы речи и отдельно время системного ожидания ASR.

На каждом M3/M4 LLM-вызове сохраняются исходный текст, raw LLM response, валидированный Query, версия/hash prompt, температура, requested/response model, provider (когда его возвращает RouterAI), `Tllm`, токены и тип ошибки. Ошибки провайдера/структуры не расходуют пользовательскую попытку; семантически неверный, но исполнимый Query — расходует. После начала M3/M4-сбора model/prompt/temperature не смешиваются внутри одного экспериментального тома.

### ASR benchmark

`benchmarks/asr_routerai_benchmark.ipynb` записывает одну фиксированную русскую фразу с микрофона в WAV и отправляет один и тот же файл в Nemotron 3.5 ASR и Qwen3-ASR-0.6B. Notebook выводит transcript, latency, нормализованное точное совпадение и WER. Ключ берётся из `ROUTERAI_API_KEY` или запрашивается скрытым вводом и в notebook не сохраняется. После выбора модели перенесите её идентификатор в `backend/config.json` (`asr_model`).

## M5: RouterAI agent

M5 переносит в backend протокол из `benchmarks/m5_agent_benchmark.ipynb`: та же `deepseek/deepseek-v4.1-flash`, `temperature=0`, последовательный tool loop и семь атомарных инструментов. Лимит — `m5_max_llm_steps=12`. Tool calls выполняются в порядке ответа модели; скрытые chain-of-thought данные не запрашиваются и не сохраняются. `in/not_in` принимают только списки — невалидный аргумент не меняет состояние агента.

M5 хранит наблюдаемую trajectory отдельно: LLM/tool шаги, аргументы и результаты, latency, tokens/provider/model, termination и финальный `Query`. Затем финальный запрос проходит общий `ExperimentService.submit`, поэтому попытки, эталон, CSV и метрики остаются сопоставимыми с M1–M4. Task Mining M5 остаётся браузерным журналом действий участника и системного ожидания; trajectory — диагностический журнал самого агента.

Последний прогон инженерного benchmark, сообщённый для текущей конфигурации: 15 фиксированных задач × 5 повторов = 75 запусков, 73 успешных и 2 ошибки, то есть **97,33%**. Это проверка надёжности агентного pipeline на benchmark-наборе, а не показатель точности или эффективности M5 в пользовательском эксперименте. Загруженный notebook в исходном архиве содержит более ранние сохранённые outputs; число 73/75 фиксируется как результат отдельного пятиповторного прогона.

## Аналитика для статьи

Для быстрого локального просмотра откройте [`fast_watcher.html`](fast_watcher.html) двойным щелчком в современном браузере. Войдите на сервер по приглашению исследователя в том же браузере, нажмите «Скачать Task Mining ZIP» и перетащите скачанный ZIP в окно просмотра. При нескольких авторизациях можно указать несекретный UUID контекста исследователя (`access`). HTML не выполняет SSH, не запрашивает приглашение и не хранит данные после закрытия страницы; Docker и установка зависимостей для него не нужны.

Просмотр показывает графики Canvas, число выполненных проб, отказов «сдаться», других неуспехов, активных и неначатых проб. Есть поиск и выбор по `participant_code`, фильтры режима/уровня, таблица проб и CSV-сводка текущего выбора. Несколько сессий одного кода суммируются; тренировки по умолчанию исключены. «Сдался» определяется по `gave_up`, а не по `end_reason=attempt_limit`: эта причина используется также при обычном исчерпании попыток. Старый экспорт без `gave_up` выводится с предупреждением. Поддерживаются также `trials.csv` и JSON-снимок `/api/analytics`. Для проверки: импортируйте свежий ZIP, выберите участника и сравните количества с его строками в `trials.csv`; при повторном импорте данные заменяются, не добавляются.

После входа по приглашению исследователя доступны через origin frontend:

В локальном просмотрщике правая колонка «Результаты по режимам» прокручивается и содержит графики минимума, среднего и максимума фактического времени и числа попыток на одну пробу, а также таблицу с суммами по M1–M5. По умолчанию учитываются все завершённые пробы; переключатель позволяет оставить только успешные. Общее время (`elapsed_ms`) и активное пользование (`Tuser_active_ms`) представлены отдельными графиками и таблицами с суммой, средним, минимумом и максимумом; попытки (`attempts`) — отдельной сводкой. Активное время исключает зарегистрированную потерю фокуса, системное ожидание и длинные паузы между действиями; это оценка активности, а не полное время размышления. Отсутствующее активное время не подменяется общим. При подсчёте `attempts`: все итоговые попытки до успеха включены, активные и неначатые пробы исключены, отсутствующие значения не считаются нулями. Расчёт следует текущим фильтрам; таблица показывает число наблюдений каждого показателя. Время отображается в минутах без штрафных подстановок. Для ручной проверки выберите одного участника и режим, сопоставьте сумму времени и попыток с его завершёнными строками `trials.csv`, затем переключите расчёт на зелёные пробы.

После входа по приглашению исследователя доступны через origin frontend:

Матрица «Режим × уровень задачи» группирует пробы по M1–M5 и C1–C3 (варианты a–e объединяются по уровню). Можно выбрать активное/общее время или попытки и статистику: среднее на пробу, минимум, максимум, сумму. Ячейки показывают значение и N наблюдений; цвет обозначает величину показателя в текущем выборе, а не успешность. Итоги строк и столбцов рассчитываются по исходным пробам, без усреднения средних. Матрица следует тем же фильтрам и выбору завершённых/зелёных проб, что правая колонка. Для проверки выберите M4 и C2 и сравните ячейку с соответствующей сводкой режима.

Из всей выборки локального просмотрщика исключаются участники, у которых хотя бы одна основная проба имеет статус `pending` («Не начато»). Проверка идёт по всем загруженным основным пробам до фильтров режима/уровня; исключаются все сессии такого кода участника. Тренировочные пробы не вызывают исключение. Правило общее для списка участников, графиков, таблиц, heatmap и CSV-сводки; число исключённых видно под карточками. Загружайте полный ZIP: серверные фильтры могут скрыть неначатые пробы. Для проверки возьмите код с `pending` в исходном `trials.csv`: его не должно быть в списке и аналитике даже после выбора другого режима или уровня.

- `http://localhost:3033/api/analytics/export.xlsx` — Excel (`protocol`, `trials`, `attempts`, `events`, `interpretations`, `m4_transcriptions`, `agent_runs`, `summary`);
- `http://localhost:3033/api/analytics/export.zip` — полный CSV-архив;
- `/api/analytics/trials.csv`, `/api/analytics/summary.csv`, `/api/analytics`.

Общие фильтры: `participant_code`, `mode`, `level`, `completed_only`, `include_practice`. Например:

```text
/api/analytics/export.xlsx?mode=M1&level=1&completed_only=true
```

По умолчанию тренировки исключены. Фактические и штрафные показатели хранятся раздельно. Все времена — миллисекунды. CSV и Excel включают параметры протокола и контрольную сумму набора данных.

## Текущие границы

- Полностью доступны M1–M5. M4 использует `MediaRecorder` и RouterAI Audio Transcriptions с моделью из `backend/config.json`; Web Speech API/VPN не требуются, Firefox поддерживается при доступном микрофоне.
- Аналитические статистические тесты и графики не выполняются автоматически: исследователь получает Excel/CSV.
- Frontend построен из переиспользованных компонентов `TagInput`, `LiveSearchProgress`, `ConfirmDialog`, `AppToast`; табличная логика адаптирована из `Corpus` без чужих API/ролей.
- Для независимого нового эксперимента используйте новый Compose project name/том; не меняйте параметры набора/эталонов в существующем эксперименте. Обычное обновление приложения через `docker compose up -d --build` сохраняет совместимость существующего тома; M3/M4 LLM-конфигурация фиксируется в журнале интерпретаций; M5 agent protocol сохраняется в `m5_agent_runs`. После перехода с прежнего M3/OpenRouter на RouterAI основную выборку следует вести в новом экспериментальном томе, чтобы не смешивать разные LLM-протоколы.

Архитектура и контракты: [ARCHITECTURE.md](docs/ARCHITECTURE.md). Frontend-решения: [FRONTEND-NOTES.md](docs/FRONTEND-NOTES.md).

Выгрузить полный Task Mining / аналитику в ZIP:
```powershell
& {
    $u = ssh -i "$env:USERPROFILE\.ssh\aia_github_deploy" root@194.226.120.153 "cd /opt/article-interaction-automation/current && docker compose -p article-interaction-automation --env-file /etc/article-interaction-automation.env -f compose.yaml -f compose.prod.yaml exec -T backend sh scripts/invite.sh RESEARCHER --role researcher"
    if ($LASTEXITCODE -ne 0 -or -not $u) { throw "SSH: failed to obtain an invitation." }
    $u = ($u -join "`n").Trim()
    try {
        curl.exe --fail --silent --show-error --location --cookie-jar researcher.cookies.txt "$u" --output NUL
        if ($LASTEXITCODE -ne 0) { throw "Researcher sign-in failed. Export stopped." }
        curl.exe --fail --silent --show-error --cookie researcher.cookies.txt "https://194.226.120.153/api/analytics/export.zip" --output task-mining.zip
        if ($LASTEXITCODE -ne 0) { throw "ZIP download failed. Check authentication and server availability." }
        Write-Host "Downloaded: $(Join-Path (Get-Location) 'task-mining.zip')"
    }
    finally {
        if (Test-Path -LiteralPath researcher.cookies.txt) {
            Remove-Item -LiteralPath researcher.cookies.txt
        }
    }
}
```
Вставьте блок целиком в PowerShell. `task-mining.zip` будет создан в текущей папке. В нём есть полный CSV-экспорт, включая events с Task Mining. Откройте ZIP в `fast_watcher.html`. При ошибке SSH или HTTP блок останавливается; `--fail` не позволяет сохранить HTTP-ошибку авторизации как ZIP. Файл от прежней неудачной команды может содержать JSON ошибки вместо архива: он станет пригоден после успешной повторной выгрузки. Не публикуйте ссылку приглашения и cookie-файл.
